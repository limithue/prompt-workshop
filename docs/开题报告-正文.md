## 一、选题背景与意义

大语言模型（Large Language Model, LLM）的能力在参数层面已经固定，用户能否获得高质量输出，很大程度上取决于输入提示词的组织方式。同一模型、同一任务，仅改变提问的措辞与结构，输出质量就可能出现明显差异。这一现象使"如何写提示词"从经验技巧逐渐转变为一类可讨论、可复用的工程方法，即提示词工程（Prompt Engineering）。

对初学者而言，提示词工程的学习存在两个现实障碍。第一，方法分散。角色设定、任务描述、背景补充、输出格式约束、少样本示例等要素散落在各类经验帖与文档中，缺少统一的结构化表达。第二，效果不可见。初学者往往只看到"优化后更好"的结论，却难以直观对照"优化前后差在哪里"，因此难以建立稳定的方法认知。

本课题拟实现一个面向教学的网页演示系统，将提示词的结构化方法与效果对比放在同一界面内完成：用户输入一句自然语言需求，系统按六要素生成结构化提示词，并并排展示原始提示词与优化提示词所得到的回答。其意义在于把抽象的提示词工程方法转化为可操作、可观察的教学工具，降低初学者的理解成本，同时为课程中"评估与迭代"环节提供一个可演示的载体。

## 二、国内外研究现状

提示词工程的研究脉络可以概括为三个阶段。

第一阶段关注提示形式本身。Brown 等人提出少样本提示（Few-shot Prompting），通过在输入中给出少量示例，使模型在无参数更新的情况下完成新任务 [1]。这一工作确立了"提示即接口"的基本认识。

第二阶段关注推理过程的引导。Wei 等人提出思维链提示（Chain-of-Thought），引导模型在给出结论前先输出中间推理步骤，显著提升了多步推理任务的准确率 [2]。此后，提示设计从"描述任务"扩展到"规定思考方式"。

第三阶段转向系统化梳理与工具化。Liu 等人对提示方法进行了系统综述，将提示划分为预训练、提示构造与预测三个阶段，并指出提示模板的设计质量直接影响下游表现 [3]。Reynolds 与 McDonell 进一步讨论了提示编程的范式，认为提示应当被视为一种可迭代的程序性表达，而非一次性提问 [4]。在人机交互层面，Zamfirescu-Pereira 等人的用户研究发现，非专业用户在编写提示时普遍缺乏结构化意识，且难以判断提示失败的原因 [5]。

综合来看，现有研究在方法层面已较为充分，但在教学与演示层面仍存在空白：多数工具面向开发者，强调接口调用与批量评测，缺少面向初学者的、把"结构化方法"与"效果差异"同时呈现的轻量工具。本课题正是从这一空白切入。

## 三、研究内容与目标

本课题的研究内容围绕一个可运行的演示系统展开，具体包括三部分。

第一，结构化提示词的要素模型设计。将提示词拆解为角色、任务、背景、输出格式、参考示例、约束条件六个要素，并为不同任务场景（通用任务、编程开发、文案写作、数据分析、学习辅导）设计对应的要素模板，使同一套结构能够适配不同领域。

第二，提示词自动生成与可编辑机制。系统根据用户输入的自然语言需求与所选场景，填充六要素并合成完整提示词；六个要素均可单独修改，修改结果实时同步至完整提示词，保证生成结果不是黑盒。

第三，效果对比与验证机制。在同一需求下，分别以原始自然语言与优化后提示词调用模型，将两份回答并排呈现，使结构差异带来的效果差异可以被直接观察。

对应的研究目标有三项：

1. 完成六要素提示词模型的场景化设计，覆盖不少于 5 类常见任务场景。
2. 实现可本地运行的单页演示系统，在不配置外部接口的情况下也能完整演示生成与对比流程。
3. 通过对比实验，说明结构化提示词在输出完整性与结构清晰度上的差异。

## 四、技术路线与实施方案

系统采用前后端一体的轻量方案：前端为单页网页，使用原生 HTML、CSS 与 JavaScript 实现，不引入构建工具与框架依赖，保证在任意浏览器中双击即可运行，便于课堂演示与作业提交。整体技术路线分为四个阶段。

第一阶段为需求分析与要素建模。梳理提示词工程的通用结构，确定六要素的字段定义与填写规则，并针对五类场景设计差异化模板。

第二阶段为生成引擎实现。以规则驱动的方式，将用户输入与场景模板结合，生成结构化的提示词对象；同时提供六要素的编辑能力与完整提示词的实时合成。

第三阶段为对比模块实现。系统提供两种运行模式：演示模式内置场景化回答模板，无需外部服务即可完成对比演示；真实接口模式兼容 OpenAI Chat Completions 协议，可接入 DeepSeek、通义千问、Kimi 等模型进行真实调用。接口密钥仅保存在浏览器本地存储，不写入代码。

第四阶段为验证与整理。选取若干典型需求，分别用原始提示词与优化提示词生成回答，从结构完整性、信息密度与可执行性三个维度进行定性对比，并整理形成结题材料。

关键技术选型说明：选择原生前端而非框架，是因为本系统页面规模小、交互逻辑集中，引入框架反而增加部署与演示成本；选择双模式运行，是为了解决课堂环境网络受限、密钥不便配置的问题，保证演示过程不依赖外部条件。

## 六、预期成果

1. 一个可独立运行的提示词工坊网页系统，支持六要素生成、逐项编辑、效果对比与提示词复制。
2. 一套覆盖五类任务场景的提示词模板，可作为同类教学工具的参考。
3. 一份结题报告，说明系统设计思路、实现过程与对比验证结果。

本课题的预期局限在于：对比实验以定性观察为主，样本规模有限，暂不构成统计意义上的结论；系统的提示词生成依赖规则模板，对高度专业或开放式任务的适配能力有限。这些局限将在结题报告中如实说明。
